# 🎯 나만의 퀴즈 게임

## 개발 환경

- OS: Windows (Git Bash / MINGW64)
- Python: 3.14.6
- Git: 2.47.0.windows.2
- Editor: VS Code 1.130.0

![version](docs/screenshots/version.png)

## 프로젝트 개요

Python 기본 문법과 객체지향(클래스), JSON을 이용한 데이터 저장을 학습하기 위해
터미널에서 동작하는 퀴즈 게임을 직접 구현한 프로젝트입니다.
사용자는 퀴즈를 풀고, 새로운 퀴즈를 추가/수정/삭제하고, 등록된 퀴즈 목록과
최고 점수를 확인할 수 있으며, 프로그램을 종료해도 데이터가 유지됩니다.
또한 Git을 이용해 기능 단위로 커밋을 남기고, 브랜치를 나눠 작업한 뒤 병합하며
개발 이력을 관리했습니다. 필수 기능 완성 이후에는 랜덤 출제, 문제 수 선택,
힌트, 퀴즈 삭제, 게임 기록 히스토리 등 보너스 기능과, 전역 뒤로가기/종료
네비게이션, 도움말, 즉시 저장, 퀴즈 수정 같은 사용성 개선도 추가로
구현했습니다.

## 퀴즈 주제와 선정 이유

IT 및 비즈니스를 공부하는 학습자로서, 개발 기초 상식과 일반 상식을 함께
복습할 수 있는 퀴즈를 직접 만들어보고 싶어 이 주제를 선정했습니다.

## 실행 방법

```bash
python main.py
```

실행 후 메뉴에 나오는 번호(1~8)를 입력해 원하는 기능을 선택합니다.
대부분의 입력창에서 `b`를 입력하면 이전(메뉴)으로 돌아가고, `q`를 입력하면
지금까지의 변경사항을 저장하고 즉시 종료합니다. `?`를 입력하면 도움말이
표시됩니다.

## 기능 목록

### 기본 기능

- **퀴즈 풀기**: 등록된 퀴즈를 원하는 문제 수만큼, 무작위 순서로 풀고 채점 결과와 점수를 확인합니다.
- **퀴즈 추가**: 문제, 선택지 4개, 정답 번호(1~4), (선택) 힌트를 입력해 새 퀴즈를 등록합니다. 문제/선택지는 빈 값을 허용하지 않습니다.
- **퀴즈 목록**: 현재 등록된 퀴즈의 문제 목록을 확인합니다.
- **점수 확인**: 지금까지의 최고 점수와 총 플레이 횟수를 확인합니다. (아직 풀지 않았다면 안내 메시지 출력)
- **입력 예외 처리**: 공백 제거, 숫자 변환 실패, 범위 밖 입력, 빈 입력을 모두 안내 후 재입력 처리합니다.
- **안전 종료**: Ctrl+C, 입력 스트림 종료(EOFError) 발생 시에도 데이터를 저장하고 안전하게 종료합니다.
- **데이터 복구**: 데이터 파일이 없거나 손상된 경우 기본 퀴즈 데이터로 자동 복구합니다.

### 보너스 기능

- **랜덤 출제**: 퀴즈 풀기 시 `random.sample`로 문제 순서를 매번 무작위로 섞어서 출제합니다.
- **문제 수 선택**: 전체 퀴즈 중 몇 문제를 풀지 직접 선택할 수 있습니다.
- **힌트 기능**: 힌트가 등록된 문제는 정답 입력창에서 `h`를 눌러 힌트를 볼 수 있으며, 사용 시 미리 점수 차감을 안내하고 해당 문제는 0.5문제로 처리됩니다.
- **퀴즈 삭제**: 등록된 퀴즈 목록에서 번호를 선택해 삭제하며, 실수 방지를 위해 한 번 더 확인(y/n)을 받은 뒤 파일에 반영합니다.
- **게임 기록 히스토리**: 게임을 할 때마다 날짜/시간, 푼 문제 수, 점수를 기록해 누적 조회할 수 있습니다.

### 추가 사용성 개선

- **전역 네비게이션**: 대부분의 입력창에서 `b`(이전 메뉴로), `q`(저장 후 종료)가 공통으로 동작합니다.
- **도움말**: 입력창에서 `?`를 입력하면 사용 가능한 네비게이션 안내를 보여줍니다.
- **즉시 저장**: 종료를 선택하지 않아도, 메뉴에서 어떤 기능을 실행할 때마다 바로 `state.json`에 반영됩니다.
- **퀴즈 수정**: 등록된 퀴즈를 선택해 문제/선택지/정답/힌트를 다시 입력할 수 있으며, 각 항목에서 Enter만 누르면 기존 값이 그대로 유지됩니다.

## 데이터 파일 설명 (state.json)

- 경로: 프로젝트 루트의 `state.json`
- 인코딩: UTF-8
- 역할: 등록된 퀴즈 목록, 최고 점수, 게임 기록을 저장하여, 프로그램을 종료했다가
  다시 실행해도 데이터가 유지되도록 합니다. 메뉴에서 어떤 기능을 실행할 때마다
  즉시 반영되어, 강제 종료 상황에서도 데이터 유실을 최소화합니다.
- 파일이 없거나 손상된 경우, 프로그램이 자동으로 기본 퀴즈 5개로 복구합니다.
- 스키마:

```json
{
    "quizzes": [
        {
            "question": "Python의 창시자는?",
            "choices": ["Guido van Rossum", "Linus Torvalds", "Bjarne Stroustrup", "James Gosling"],
            "answer": 1,
            "hint": "네덜란드 출신 프로그래머입니다."
        }
    ],
    "best_score": 100,
    "history": [
        {
            "datetime": "2026-07-29 21:30:00",
            "total_questions": 3,
            "correct_count": 3,
            "score": 100
        }
    ]
}
```

- `quizzes`: 퀴즈 목록 (문제, 선택지 4개, 정답 번호 1~4, 힌트는 없으면 `null`)
- `best_score`: 최고 점수 (아직 한 번도 풀지 않았다면 `null`)
- `history`: 게임을 할 때마다 쌓이는 기록 (일시, 푼 문제 수, 정답 수, 점수)

## 학습 내용 정리

### Python 기초

- **변수를 왜 사용하는지**: 값에 이름을 붙여 저장해두면, 그 값을 여러 번 재사용하거나
  나중에 다른 값으로 바꿔가며 코드를 재사용할 수 있습니다. 예를 들어 `DATA_PATH`,
  `best_score` 같은 변수를 이용해 파일 경로나 점수를 코드 곳곳에서 참조했습니다.
- **int, str, bool, list, dict의 차이**: `int`는 숫자(정답 번호, 점수), `str`은 문자열
  (문제 내용), `bool`은 참/거짓(정답 여부 판단 결과), `list`는 순서 있는 여러 값의 묶음
  (선택지 4개, 퀴즈 목록, 게임 기록), `dict`는 키-값 쌍으로 이루어진 데이터(JSON으로
  저장할 때의 `to_dict()` 결과, 게임 기록 한 건)로 각각 역할이 다릅니다. 또한
  힌트가 없는 문제는 `None`(파이썬)이 JSON의 `null`로 저장되어, 0이나 빈 문자열과는
  구분되는 "값이 아예 없음"을 표현합니다.
- **if/elif/else 활용**: `main.py`의 메뉴 분기(1~8번 중 어떤 기능을 실행할지)와
  `check_answer()`의 정답 판정, 힌트 사용 여부 판단, `b`/`q`/`?` 입력 처리 등에
  사용했습니다.
- **for와 while의 차이**: 정해진 횟수(퀴즈 개수, 선택지 4개, 게임 기록 개수)만큼
  반복할 땐 `for`를 사용했고(`for idx, quiz in enumerate(...)`), 몇 번 반복될지
  모르고 "조건을 만족할 때까지" 반복해야 하는 경우(사용자가 올바른 값을 입력할
  때까지 재입력받기)에는 `while`을 사용했습니다.
- **함수(매개변수/반환값)**: `print_menu()`, `get_menu_choice()`, `_read_line()`,
  `_get_nonempty_text()`, `_get_answer_input()`, `_get_question_count()`,
  `_get_delete_index()`, `_get_choice_answer()`처럼 반복되는 입력 검증 로직을
  함수로 분리해 재사용했고, `check_answer(user_answer)`처럼 매개변수를 받아
  처리한 뒤 값을 반환값으로 돌려주는 방식을 활용했습니다.

### 클래스와 객체

- **클래스를 왜 사용했는지**: `Quiz`는 "문제 하나"가 가진 데이터(문제, 선택지, 정답,
  힌트)와 행동(출력, 채점)을 하나로 묶었고, `QuizGame`은 "게임 진행"이라는 별개의
  책임(메뉴별 동작, 점수/기록 관리, 공통 입력 처리)을 묶었습니다. 이렇게 역할을
  나누면 한쪽을 수정해도 다른 쪽에 영향을 덜 주고, 코드를 이해하기도 쉬워집니다.
  또한 `b`/`q` 네비게이션을 위해 `BackToMenu`, `QuitProgram`이라는 예외 클래스를
  따로 정의해, "정상적인 값 반환"과 "사용자가 흐름을 바꾸려는 신호"를 명확히
  구분했습니다.
- **`__init__`과 self의 역할**: `__init__`은 객체가 생성되는 시점에 필요한 초기값을
  설정하는 메서드입니다. `self`는 "지금 만들어지고 있는 이 객체 자기 자신"을
  가리키는 참조로, `self.question`처럼 써서 그 객체만의 데이터를 저장하고
  꺼내 쓸 수 있게 해줍니다.
- **속성과 메서드를 어떻게 나눴는지**: `Quiz`의 속성은 `question`, `choices`,
  `answer`, `hint`이고 메서드는 `display()`(출력), `check_answer()`(채점),
  `has_hint()`(힌트 보유 여부)입니다. `QuizGame`의 속성은 `quizzes`, `best_score`,
  `history`이고 메서드는 `play()`, `add_quiz()`, `edit_quiz()`, `list_quizzes()`,
  `show_best_score()`, `delete_quiz()`, `show_history()`, 그리고 공통 입력을
  담당하는 `_read_line()` 등입니다. 퀴즈 수정 시에는 새 `Quiz` 객체를 만들어
  기존 위치의 객체를 통째로 교체하는 방식을 사용했습니다.

### 파일 입출력

- **파일을 열고 읽고 쓰는 과정**: `open()`으로 파일을 열고, `json.load()`로
  내용을 읽어 Python 객체로 변환하거나, `json.dump()`로 Python 객체를 파일에
  씁니다. `with open(...) as f:` 구문을 사용해 작업이 끝나면 파일이 자동으로
  닫히도록 했습니다.
- **JSON을 왜 사용했는지**: JSON은 Python의 딕셔너리/리스트 구조와 거의
  동일해서 변환이 쉽고, 사람이 읽기도 쉬우며, 다른 언어나 프로그램과도
  데이터를 주고받기 편한 표준 형식이기 때문입니다.
- **try/except 사용처**: `load_state()`에서 JSON 파일이 손상되었을 때
  (`json.JSONDecodeError`)와 구조가 예상과 다를 때(`KeyError`, `TypeError`),
  `save_state()`에서 파일 쓰기 중 오류가 발생할 때(`OSError`), 그리고
  `main()`에서 Ctrl+C나 입력 스트림 종료가 발생할 때(`KeyboardInterrupt`,
  `EOFError`) 각각 사용해 프로그램이 비정상 종료되지 않도록 처리했습니다.
  추가로, 사용자가 `b`/`q`를 입력했을 때는 `BackToMenu`/`QuitProgram`이라는
  직접 정의한 예외를 발생시키고 `main.py`에서 잡아 처리하는 방식으로,
  "정상 흐름 제어"에도 예외 처리 개념을 활용했습니다.

### Git 기초

- **init, add, commit, push, pull, checkout, clone의 역할**:
    - `git init`: 현재 폴더를 Git이 추적하는 저장소로 만듭니다.
    - `git add`: 변경된 파일을 다음 커밋에 포함시킬 준비(스테이징)를 합니다.
    - `git commit`: 스테이징된 변경사항을 하나의 이력으로 저장합니다.
    - `git push`: 로컬 커밋을 원격 저장소(GitHub)에 업로드합니다.
    - `git pull`: 원격 저장소의 변경사항을 로컬로 가져와 합칩니다.
    - `git checkout`: 다른 브랜치로 이동하거나(`-b`와 함께 쓰면 새 브랜치 생성) 파일을
      특정 시점으로 되돌립니다.
    - `git clone`: 원격 저장소 전체를 새 로컬 디렉터리로 복제합니다.
- **브랜치를 어떻게 만들고 병합했는지**: `git checkout -b feature/이름`으로
  기능별 브랜치를 만들어 작업한 뒤, 작업이 끝나면 `main`으로 돌아와
  `git merge feature/이름`으로 병합했습니다. (예: `feature/readme`,
  `feature/refactor-quiz`, `feature/random-order`, `feature/select-count`,
  `feature/hint`, `feature/delete-quiz`, `feature/score-history`,
  `feature/edit-quiz`)
- **clone/pull 실습에서 무엇을 확인했는지**: 별도 폴더에 저장소를 `git clone`으로
  복제한 뒤, 그 폴더에서 README를 수정하고 `git push`로 원격 저장소에 반영했습니다.
  이후 원래 작업 폴더에서 `git pull`을 실행해 "Fast-forward"로 그 변경사항이
  정상적으로 반영되는 것을 확인했습니다. (`docs/screenshots/pull.png` 참고)

## 알려진 한계와 개선 방향

- 현재 퀴즈/기록 데이터는 `state.json` 파일 하나에 전부 저장하고, 조작이 있을
  때마다 파일 전체를 다시 읽고 씁니다. 지금 규모(퀴즈 수십 개 이하)에서는
  문제가 없지만, 퀴즈가 수천 개 이상으로 많아지면 매 조작마다 전체 파일을
  다시 쓰는 방식이 비효율적이고, 특정 퀴즈를 찾는 데도 리스트를 처음부터
  훑는 방식(`O(n)`)이라 느려질 수 있습니다. 데이터가 커질 경우 SQLite 같은
  경량 데이터베이스로 전환하거나, 변경분만 반영하는 방식을 고려할 수 있습니다.
- 게임 기록(`history`)은 별도의 서버나 데이터베이스가 아니라 로컬 `state.json`
  파일에만 저장되므로, 실행하는 컴퓨터(또는 폴더)마다 독립적으로 기록이
  쌓입니다.
- `b`/`q`/`?`를 전역 네비게이션 키워드로 사용하는 방식은, 자유 텍스트를
  입력받는 항목(문제, 힌트 등)에서 사용자가 정말로 "b"나 "q" 한 글자만
  입력하고 싶은 경우와 이론적으로 충돌할 수 있습니다. 정답 입력은 항상
  숫자로 제한되어 있어 실질적인 문제는 없지만, 더 엄격하게 하려면 `/b`,
  `/q`처럼 구분되는 문법을 쓰는 방법을 고려할 수 있습니다.
